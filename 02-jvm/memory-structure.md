## 二、各区域详解

### 2.1 程序计数器（PC Register）

- 线程私有，存储当前执行指令的地址
- 唯一不会 OOM 的区域
- 执行 Native 方法时值为空

### 2.2 虚拟机栈（VM Stack）

每个线程一个栈，每个方法创建栈帧，栈帧包含：

| 组成 | 说明 |
|------|------|
| 局部变量表 | 方法参数和局部变量，基本类型存值，引用存指针 |
| 操作数栈 | 计算的中间数据 |
| 动态链接 | 指向运行时常量池的引用 |
| 返回地址 | 方法调用后的返回位置 |

**异常：**
- StackOverflowError：栈深度超过 JVM 限制（通常递归过深）
- OutOfMemoryError：栈扩展时内存不足

### 2.3 本地方法栈（Native Method Stack）

为 Native 方法服务，HotSpot 将其与虚拟机栈合并。

### 2.4 Java 堆（Heap）

**分代结构：**

```
              ┌─────────────────────────┐
              │         Young Gen       │
              │  ┌──────┬──────┬──────┐ │
              │  │ Eden │  S0  │  S1  │ │
              │  │ (80%)│(10%) │(10%) │ │
              │  └──────┴──────┴──────┘ │
              └─────────────────────────┘
                          │
                          ▼ 经过多次 GC 晋升
              ┌─────────────────────────┐
              │        Old Gen          │
              │    (Tenured Space)      │
              └─────────────────────────┘
```

**追问：对象如何从 Young Gen 晋升到 Old Gen？**

1. **年龄晋升**：对象在 Survivor 区每熬过一次 Minor GC，年龄 +1，达到 `-XX:MaxTenuringThreshold`（默认 15）后晋升
2. **动态年龄判断**：Survivor 区中相同年龄的对象大小总和 > Survivor 的 50%，大于此年龄的对象直接晋升
3. **大对象**：超过 `-XX:PretenureSizeThreshold` 的对象直接进入老年代
4. **空间担保**：Minor GC 后 Survivor 放不下，直接放入老年代

### 2.5 方法区（元空间）

| 版本 | 实现 | 位置 | 配置参数 |
|------|------|------|---------|
| JDK 7 及之前 | 永久代（PermGen） | JVM 堆中 | -XX:PermSize, -XX:MaxPermSize |
| JDK 8+ | 元空间（Metaspace） | 本地内存 | -XX:MetaspaceSize, -XX:MaxMetaspaceSize |

存储内容：类元信息、运行时常量池、静态变量（JDK 8 移到堆）、JIT 编译代码缓存。

**追问：为什么用元空间替代永久代？**

1. 永久代有固定大小上限（不易调整），容易 OOM
2. 元空间使用本地内存，仅受物理内存限制
3. HotSpot 和 JRockit 融合（JRockit 没有永久代）

### 2.6 直接内存

- 不属于 JVM 运行时数据区
- NIO 通过 ByteBuffer.allocateDirect() 分配
- 通过 Unsafe 类操作，受 `-XX:MaxDirectMemorySize` 限制
- OOM 时注意检查直接内存使用情况

## 三、对象创建过程

```
1. 类加载检查         → 检查类是否已被加载、解析、初始化
2. 分配内存            → 指针碰撞（Bump the Pointer）或 空闲列表（Free List）
3. 初始化零值          → 将内存空间初始化为零值
4. 设置对象头（Mark Word） → 设置哈希码、GC 年龄、锁标志等
5. 执行 init 方法      → 构造函数、初始化块
```

**追问：指针碰撞 vs 空闲列表？**

- **指针碰撞**：内存规整时，已使用和空闲内存中间放一个指针作为分界，分配时移动指针。Serial、ParNew 等带压缩的收集器使用。
- **空闲列表**：内存不规整时，维护空闲内存列表，分配时从列表中找到合适空间。CMS 等不压缩的收集器使用。

## 四、对象的内存布局

```
┌─────────────────┬─────────────────┬──────────────────┐
│   对象头         │   实例数据       │    对齐填充        │
│ (Mark Word +    │ (成员变量)       │ (8 字节倍数)      │
│  Klass Pointer) │                 │                   │
└─────────────────┴─────────────────┴──────────────────┘
```

### Mark Word（32 位为例）

| 锁状态 | 标志位 | 存储内容 |
|--------|--------|---------|
| 无锁 | 01 | hashcode、分代年龄 |
| 偏向锁 | 01 | 线程 ID、epoch、分代年龄 |
| 轻量级锁 | 00 | 指向栈帧中锁记录的指针 |
| 重量级锁 | 10 | 指向 Monitor 的指针 |
| GC 标记 | 11 | 空 |

## 面试追问集

**Q：内存泄漏 vs 内存溢出？**

- **内存泄漏（Memory Leak）**：不再使用的对象仍然被引用，无法被 GC 回收
- **内存溢出（OOM）**：内存不足，无法为新对象分配空间

内存泄漏常见原因：ThreadLocal 未清理、集合静态持有对象、未关闭的连接/流。

**Q：JDK 8 的字符串常量池在哪里？**

在堆中（JDK 7 已经移出永久代），不再是方法区的一部分。
